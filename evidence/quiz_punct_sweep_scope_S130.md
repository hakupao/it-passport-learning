## 4. リスク

1. **中問 probe (D-167) と COPY marker**: `chumon_groups.json` の probe は committed evidence (`chumon_preamble_S114.json` 等) の先頭 40 字 (空白除去、句読点の正規化なし) で、A7 は表示 stem が probe を含むことを検査、`--check` は登記簿の再生成一致を検査。窓内を 1 字でも変えると落ちる。窓に対象字形があるのは **2012h24h-q089〜q092 と 2015h27a-q089〜q092 の 8 題 (窓内の 、 各 1)**。窓の外だけ変えると field 内混在 (D-170 違反) になるので script は**この 8 field を丸ごと据え置く** (chumon-probe-field 102 字形)。
   - **残る D-170 負債**: 据え置きは窓だけでなく 8 題の題幹全体 (102 字形)。2012h24h の 、 85 個は全てこの 4 題にあり、r1 tier で同 exam の R1 は **85 → 0** (exam 全体が 、 の型 = D-170 が狙った典型がそのまま残る)。2015h27a も 4 題分が残る。evidence を直すのは D-167 で禁止 → 解消には「probe を句読点正規化後で比較する」ADR (crosscheck A7 と groups-build の probeOf を normStr 相当に) が要る。
   - **raw 層との差**: 8 題とも raw `stem_jp` (questions / bank / by_year、非表示) は clean と別文 (OCR 由来) で probe を含まないため**走査される**。表示層 (stem_jp_clean) は据え置き → 層間で字形だけずれる (machdiff は字形を同一視するので見えない)。apply の reviewer はこの差を想定すること。
   - **COPY marker**: groups-build の COPY 表 (lightweight-copy 5 組) は jp の cut marker を `stem_jp_clean` から文字列一致で探し、無ければ throw する。marker 内に対象字形があるのは **2011h23a-q093「〔A さんが書き出したメモ〕の(1)〜(5)を実施する順番」の 〜 だけ** → R3 で消えるので script は同 field を丸ごと据え置く (copy-marker-field 1)。script 末尾で A7 相当 (全 50 組・全メンバーの stem_jp_clean が jp probe を含む) と 5 marker の残存を assert (3 tier とも PASS)。lightweight-copy 組の probe 窓には対象字形なし。
2. **machdiff の allowlist**: `TRANSCRIPT_PREFIX_ADJUDICATED` の sha1 / head は `nd = norm(shown)` の切片から計算 (`scripts/quiz-fidelity-machdiff.mjs:211-216`)、normStr は ，、, と 〜～~ を同一視し空白を消す → **走査で sha1 は変わらない (9 件とも安全)**。裏返すと machdiff はこの走査を検出できないので、apply の検証は script 内の正規化 assert と構造 assert が担う。
3. **選択肢パーサ**: `quizRichText.parseChoice` は「，|、|, 」を区切りにし、KEY_AT は ，、, を前置区切りとして認識 → 置換後も同じ区切り。zh / en の表示は jp を hint にするので、jp 置換で訳の分解が変わらないことも assert 済み (0 件)。
4. **vitest / e2e**: corpus の文字列を固定する test は無い (quizRichText.test の「[表] a: 外観, b: 客観的な」は合成入力)。`quizCorpusInvariants.test` = keys-crosscheck A1〜A7 + chumon `--check` → §4-1 の据え置きで不変。apply 後に `pnpm vitest` で確認すること。
5. **規模・衝突 (R2)**: all tier は 5,431 field / 1,222 file。.phase1 sidecar を含む全 exam を一度に書くので、他 lane の lock 中は不可。Rule A (> 50% rewrite ではないが件数が大きい) の N 標本独立抽検を apply 前後で要する。
6. **方針の食い違い (R2)**: X1〜X4 fixer は「ASCII「, 」は exam 全体の型 (⑨、不変)」として触らず、D-170 は 、 だけを扱った。源は ASCII「, 」の箇所も ，なので R2 は源への忠実化だが、新しい決定 (D 番号) が要る。
7. **擬似言語・式の区切り**: 源は宣言や関数引数も ，の可能性があるが (D-162 は「区切りは原典どおり」)、本走査は code / formula を一律保護。式の区切り字形は別判断 (115 + 16 字形)。
8. **符号位置 ～**: 画像では U+FF5E と U+301C を区別できない。～ は corpus 既存是正との一貫性による規約。
