## Task C — hook の型 (zh 34 / en 75)

- 10 件 (zh 5: C01〜C05、en 5: C06〜C10) を読んだ。**10 件とも混入ではなく、約定の問題** (印を付けるべきもの) です。
- 理由:
  - **内容は意図どおり**。D-195 §6 は記憶フックに「語源・字形・対比など定義と別の手がかり」を求めている。日本語の語や字を分解するのは、この規則に沿った書き方です。
  - **約定は印を求めていて、hook を除外していない**。
    - 訳者への指示 (`scripts/textbook-v2.workflow.mjs` の localiser 規則) は「zh / en 本文中で試験の日本語表記を示すところは [[jp:]] を併記」としている。
    - 平文でよいと明示されているのは analogy・総表 extra・図ラベル・caption だけで、hook については何も書かれていない。
  - **実際の扱いは揃っていない**。zh + en の hook 2,390 件のうち `[[jp:]]` を含むのは 155 件。C01 は 1 文の中で [[jp:テンキー]] には印があり、“テン” には無い。
- **実害** (軽微): `apps/web/src/lib/textbook/inline.ts:58-65` は `[[jp:]]` だけを `<span lang="ja">` にする。
  - 印の無い日本語は、zh / en のページの lang のまま描かれる。zh ページでは日本字形の漢字に中国語の字形・フォントが当たり、読み上げも中国語・英語になる。
  - 互換欄の memory_hook に派生し、glossary にも出る。
- **走査の規模は小さく数えられている**。zh の 34 件は仮名を含むものだけです。
  - en の hook の当たり 75 件のうち 68 件で、zh の兄弟が同じ漢字を `[[jp:]]` の外に含む。そのうち 63 件は zh 側で当たっていない。
  - したがって zh の hook の対象は少なくとも約 97 件 (34 + 63) ある。仮名・日本字形を含まない分解 (例: C09 漏 / C10 演 の zh) は数に入っていない。
- 付記: C06 の ja hook「固定はその場に据えて動かさないこと」は定義の言い換えで、D-195 §6 が禁じている。言語ではなく内容の問題です。

**判定**: 「印を付けるべき」約定の問題です。今のままで読めないものも、本当の混入も無い。方針を決める必要があります (hook に印を付けるか、D-202 で hook を平文の例外に加えるか)。決まるまでは、L5 の常設ゲートで hook を許可リストに入れるか、別の扱いにする。

### 走査に足すとよい規則 (L5 の候補)

- **R-zh-jpform**: zh 欄で `[[jp:]]` と括弧の外にある日本の字形 (簡体に無い字)。標本の外の検索では、訳文側の誤検出はほとんど無かった。hook の 標 なども拾える。
- **R-zh-jpword**: 日本語だけの語の語彙表 (正解 / 分野 / 立案 / 取扱 / 見積 / 手続 …)。WARN にとどめ、fixture で許可する。
- R-same が 12 字以下を見ないので、短い UI ラベルを写したもの (問 / 解説 は意図どおりだが、意図しない写しも) が見えない。ui-messages に限り下限を外し、D-189 の fixture と組み合わせる。

### 漢字だけの混入に専用の 1 回が要るか

**要る。ただし無作為の通読ではなく、語彙で抜き出すやり方で**。

- 無作為 60 欄では 1 件 (zh) しか出ず、率の上限は約 25% と幅が広い。もう 60 欄読んでも精度はあまり上がらない。
- 一方、語彙で狙うと 正解 112 / 分野 12 / 立案 15 がすぐ出た。

L4 に「zh の日本語語彙の 1 回」を置き、規則の候補 R-zh-jpword / R-zh-jpform をその道具にするのが費用に見合う。ja 欄の中国語の言い回しと en 欄の他言語は、20 欄ずつでは 0 件だったので、専用の回は今は要らない (ただし上限は約 14%)。
