## §2. 新欠陥クラス — 「意味的に成立するが源と異なる」表示テキスト

### 発見の経緯

解説本文の OCR caveat 体系スキャン中、q062 が正規表現に**誤ヒット** (「条件が崩れます」の「崩れ」)。
ついでに raw stem を見たところ源と食い違い、源ページ page-24 を実読したら**正解肢ウ自体**が
源「（A∩B）は，（A∪B）の部分集合である」→ dataset「(A∩B)は，**B**の部分集合である」と置換されていた。

### なぜ全ゲートを素通りしたか (構造的な理由)

**両方とも数学的に真** (A∩B ⊆ B も A∩B ⊆ A∪B も常に成立) で、key ウ とも矛盾しない。ゆえに

| ゲート | 素通りした理由 |
|---|---|
| generate key-guard | 矛盾が無いので `stem_corruption_suspected=false` |
| in-pipeline reviewer | 解説は腐敗版に対して整合しているので PASS |
| Rule A critic | stem/choices を**与えられたまま**評価する (非図問で源ページを読まない) |
| S101 決定的 detector | `0→O` 等の字形シグナルに依存 → 意味的置換は不可視 |

解説本文も A∩B ⊆ B を論じており、正解肢の説明が源の主張と別物になっていた。
**この問は偶然浮上した**——既存のどの仕組みも構造的にこのクラスを見られない。

### 対策 (新設スクリプト 6 本)

| スクリプト | 役割 |
|---|---|
| `quiz-s7x-fidelity-prep.mjs` | `stem_resourced_s7x` / `choices_resourced_s7x` の高リスク問を抽出 |
| `quiz-s7x-fidelity.workflow.mjs` | 源ページ PNG を実読し表示テキストと逐字 diff。`agent_type` で独立二読 |
| `quiz-fidfix-S109.mjs` / `-2014h26a.mjs` | 保真是正 (raw/clean/choices、assert-once) |
| `quiz-fidfix-repair-prep.mjs` / `.workflow.mjs` / `-apply.mjs` | zh/en・解説の連帯修復 (書込パスに LLM なし) |

プロンプトの要点: **源を先に読み書き起こしてから dataset と突き合わせる**、
**「dataset 側も日本語として自然/内容的に真」でも源と異なれば必ず報告する** (もっともらしさは一致の証拠でない)。
