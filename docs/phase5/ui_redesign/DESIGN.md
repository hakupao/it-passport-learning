## 1. 意图

用户:「什么都不好，体验差」「配色和 layout 也不喜欢」「目标就是做题，简简单单就很好，但 AI 感太重」。

现状问题 (S132 §1 截图): 没有首页、做题是一回 100 题的长卷、三套主题外观不一致、信息层级平、AI 老师先给 API key 表单、残留过时文案。

**一句话目标**: 把 app 从"资料仓库"变成"每天告诉你做什么、然后让你一题一题安静做下去"的过去问笔记本，外观像一本好的日本参考书，而不像 SaaS 模板。

### 目标
- G1 打开就知道今天做什么 (「今日」首页，一个主按钮)。
- G2 做题是主角: 一题一屏、答完即看解析、成组做、有总结、错题会回来。
- G3 全站一套外观 (A4 参考书改)，删除三套主题。
- G4 题面与真题一致: 日文原文默认，翻译为开示层。
- G5 教科书 / 辞典 / AI 老师 / 学习记录 全部重做，并与做题连成闭环。

### 非目标
- 本轮不做手机版 (D-183；但 token 与 layout 要能直接移植)。
- 不改数据层内容 (题目、翻译、解析、教科书、辞典的语料不动)。
- 不新增 AI 生成内容；AI 老师的能力与 D-181 相同，只改入口和位置。
- 不做账户系统 / 多用户；同步仍只对 owner (D-180)。

### 反目标 (做到了也算失败)
- 看起来像 SaaS 模板: 灰底白圆角卡片满屏、蓝色强调、胶囊徽章、`⌘K`/`Enter` 键帽提示、对称卡片网格、到处是灰色说明小字。
- 打乱 ア〜エ 顺序。
- 复习队列无上限、越积越多。
- 惩罚式游戏化 (扣能量、强制连续打卡)。
- 弹窗打断做题。
- 题面文字和现在显示的不一致 (显示保真退化)。

## 3. 视觉系统 (D-185)

来源: A4 mockup (`mockups/A4-Practice.dc.html`, `mockups/A4-Home.dc.html`) + 书籍誌面共通惯例 (墨 + 1 特色的 2 色印刷、问题面淡色平网、反白编号、× ○ 逐项、頻出度 ★、出典行、解答栏、要点框) + 真题冊子 (黑体、宽行距、「問N」悬挂缩进、短选项 4 列横排、全角「，」)。

### 3.1 Token (只有这些；所有组件只引用 token)
| token | 值 | 用途 |
|---|---|---|
| `ink` | `#1B2A4A` 藏青 | 正文、标题、主按钮底、反白标签底、"你的答案"标记 |
| `ink-muted` | `#5A6680` | 次要文字 (对白底 ≥ 4.5:1) |
| `spot` | `#B8501A` 赤茶 | 唯一的特色: 「問 N」、ア〜エ 方块、正解圈、×、重要语、波浪下划线、要点框 |
| `tint` | `#FBF0E8` | 问题面平网 / 你选的那一行解析 |
| `paper` | `#FFFFFF` | 底色 |
| `rule` | `#D5DAE3` | 细线 |
| `rule-spot` | `#E4D3C6` | 特色系细线 |
- 对错不用红绿: 正解 = spot 圆圈 ○，你的错答 = ink 方块 + ×。(书的惯例；也避开红绿色盲问题)
- 圆角: 0〜6px。无阴影。无渐变 (波浪下划线除外)。
- 主题: 只有这一套。暗色模式 = 后续 (不在本轮)。【Claude】

### 3.2 字体
- 全站 `BIZ UDPGothic` (400/700)，经 `next/font/google`，`display: 'swap'`，`preload: false` (CJK 文件大，Google 按 unicode-range 切片；Context7 `/vercel/next.js` font API 确认了 `preload`/`variable`/`subsets` 选项)。
- 简体中文字形 BIZ UD 不全 → fallback `Noto Sans SC`。英文 fallback 系统字体。
- 删除 Geist / Geist Mono / JetBrains Mono (主题专用)。

### 3.3 组件词汇 (从书来的固定部件)
`反白标签` (ink 或 spot 底白字方块: 「問 1」「解説」「解答」「ストラテジ系」) · `选项方块` (ア〜エ，spot 底白字；你选的 = ink 底) · `要点框`「ここがポイント」(spot 细框 + spot 标题条) · `解答栏` (页底 spot 细框) · `頻出度 ★★☆` · `出典行` · `复习三格` (这题最近 3 次的 ○ / ×) · `答题卡` (本组 N 格，○ / ×) · `点线标题下划线` (spot 2px dotted) · `波浪下划线` (关键句)。
- 不用吉祥物、插画、emoji。

### 3.4 全局框架 (一个 AppShell，替代三套 shell)
- 顶部: 4px ink 顶线；左 = 站名「ITパスポート 過去問ノート」；导航 = 今日 / 练习 / 教科书 / 辞典 / 记录 (文字链接，当前项下方 spot 2px 线)；右 = 界面语言 `日 / 中 / EN` + 设置入口。
- 「AI 老师」不在顶部导航 (就地出现，见 §6.5)；`/sensei` 保留为"对话记录 + 自由提问"页，从设置菜单和就地入口进入。【Claude】
- 内容区最大宽 1240px，左右 32px；手机移植时导航变底部 tab (D-183 预留)。
- 站名不用 IPA 的 logo / 「iパス」字样 / 官网版式 (只是配色接近；避免冒充官方)。

## 5. 学习记录 v2 (阻塞性设计，Phase 1 第一件事)

### 5.1 为什么必须改
现在 `LearningRecord v1` (`src/lib/learning/record.ts`) 每题只存**最近一次** `{choice, correct, at}`。错题本的"多久后再出"、复习三格、掌握度、组末总结的"比上次如何"、复习预报，都需要**作答历史**。

### 5.2 v2 结构 【Claude，锁定于 D-189；改动需 v3 迁移】
```ts
interface Attempt { at: number; choice: string; correct: boolean; src: "practice" | "mock" | "v1" }
interface LearningRecordV2 {
  v: 2;
  attempts: Record<string /*qid*/, Attempt[]>;   // 每题保留最近 K=10 次 (同一天的重复作答也存)，按全序降序
  unitsRead: Record<string, number>;             // 与 v1 相同 (最早一次)
  settings: {
    examDate?: LwwValue<string /*YYYY-MM-DD*/>;
    dailyReviewCap?: LwwValue<number>;           // 默认 30
    dailyNewTarget?: LwwValue<number>;           // 默认 10
    transDefault?: LwwValue<"hidden" | "shown">; // 默认 hidden
  };
  v2Since?: number;                              // 第一次以 v2 写入的时刻；合并取较小值 (迁移排期用，§5.5)
}
interface LwwValue<T> { value: T; at: number }
```
- `src: "v1"` = 从 v1 升格来的那一条。
- **合并仍须可交换 / 结合 / 幂等** (owner 同步的前提，v1 注释里的不变量):
  - attempts: 两边取并集 (以 `at` + choice + correct 去重)，按 v1 的全序排序后截取前 K 个。"并集再取 top-K" 对任意分组结果相同 → 满足三性质。
  - unitsRead: 取较小值 (同 v1)。
  - settings 每项: last-writer-wins，`at` 大者胜，`at` 相同按 JSON 字典序 (全序)。
- **派生而非存储**: 掌握度、到期日、错题本成员、leech 都是 attempts 的纯函数，不存 → 不需要另定合并规则。
- `v2Since`: 取较小值 (同 unitsRead)，可交换 / 结合 / 幂等。
- 体积: 编码时 `choice` 存下标 0–3、`correct` 存 0/1、`src` 存单字母，单条 ≈ 30 字节；2900 题都做满 10 次的极端值 ≈ 870KB → body 上限从 512KB 提到 1MB (服务器先行时一起改)。实际用量远低于极端值。【Claude】

### 5.3 上线顺序 (服务器先行)
现状: `/api/learning` 的 `parseRecord` 遇到 `v !== 1` 就 400，存储里的文档不合法就 500 (fail closed)。所以**客户端先发 v2 会在生产上全部失败**。
1. 服务器接受 v1 与 v2；v1 收到后升格 (`questions[qid]` → `attempts[qid] = [that]`) 再与存储合并；存储改写到新 key `learn:owner:v2`；旧 key `learn:owner:v1` 只读不删 (保底)。
2. 部署服务器、确认 v1 客户端仍然正常 (旧标签页)。
3. 再部署 v2 客户端: localStorage 新 key `itp:learn:v2`，首次启动从 `itp:learn:v1` 升格，旧 key 不删。
4. 多标签页: 新旧版本同时打开时，旧页写 v1 key、新页读 v1+v2 合并 → 不丢数据。

### 5.4 复习规则 (D-187 的"多久后再出") 【Claude；纯函数，规格即单元测试的期望值】
**输入**: 一题的 attempts、今天 (浏览器本地日期)。**排期只看每天的第一次作答** (同日重做会存下来，但不影响盒子)。

**盒子** (按天依次处理):
- 答错 → 盒 0。
- 答对 → 盒 +1；**该题第一次作答就答对** → 直接进盒 2 (7 天后再确认一次，不在 3 天后轮回)。
- 间隔: 盒 0 = 1 天、盒 1 = 3 天、盒 2 = 7 天、盒 3 = 14 天、盒 4 = 30 天；盒 5 = 掌握，不再排期 (只在随机 / 模考里出现)。
- 到期日 = 最后一个计入日 + 当前盒的间隔。

**每道做过的题恰好属于下面一类** (互斥，今日页各行不会重复计数):
| 类 | 条件 |
|---|---|
| 错题 | 有过答错，且最后一次答错之后、计入的答对天数 < 2 |
| 到期复习 | 不是错题，盒 0–4，到期日 ≤ 今天 |
| 排期中 | 不是错题，盒 0–4，到期日 > 今天 |
| 掌握 | 盒 5 |

- leech (顽固题) = 窗口 (最近 10 次) 内答错 ≥ 4 次 → 仍在错题本，但题旁和错题本里标「顽固」，并提示「读对应单元」「问 AI 老师」(Anki leech)。用窗口近似"累计"是有意的 (见 §5.2，计数器需要另一套合并规则)。错题本显示「近 10 次错 N 次」。

**每日量** (今日页与「从第 1 项开始」都按此):
- 复习上限 (错题 + 到期复习合计) 默认 30/天，设置 10–100。优先级: 错题 (最早到期在前) → 到期复习 (最早到期在前)。超出的不显示为"今天"，顺延 —— 这本身就是按天摊平，**放在 Phase 1**。
- 新题目标 默认 10/天，设置 0–50。新题 = 没做过的题；挑法: 先补"已答 < 5 题"的领域 (按頻出度高的在前)，然后按三分野的出题比例随机；抽到中問组内一题时整组一起算。
- 今日任务顺序: ① 错题 ② 到期复习 ③ 新题 ④ 推荐单元。主按钮依次走 ①→②→③ (每组 ≤ 20 题，组末总结页「继续下一项」)。

### 5.5 迁移后的第一天 【Claude】
v1 升格出来的 attempt (`src: "v1"`，只有一次作答):
- v1 答错 → 进错题本；受每日上限约束，每天最多 30 道流入 (不会第一天积压几百题)。
- v1 答对 → 视为盒 2；到期日 = `v2Since` 当天 + (题 id 的稳定哈希 mod 14) 天，把旧对题平铺到迁移后两周内。
- 服务器升格与客户端升格用同一个纯函数 (共享模块)，有单元测试。

## 6. 页面规格

### 6.1 今日 (Phase 1) — mockup `A4-Home`
- 顶部: 反白日期标签 + 考试日 (未设置时显示「设定考试日」链接，不显示倒计时)。
- 标题「今天的学习」+ 点线下划线。
- 任务清单 (最多 4 行，按此顺序，空的行不显示，数量规则见 §5.4「每日量」): ① 错题 N 题 ② 到期复习 N 题 ③ 新题 N 题 ④ 推荐单元 1 个 (规则: 最弱领域里还没读过的第一个单元；没有就省略)。每行: 勾选框 (完成后自动打勾) + 反白小标签 + 标题 + 一行明细 + 预估时间 (每题 1 分钟估算；单元用单元 JSON 的 `overview.est_minutes` —— `unit_index.json` 里没有，构建时生成 unitId → 分钟 的小表)。
- 主按钮「从第 1 项开始」= 依次进入 ① → ② → ③ 的练习组 (每组 ≤ 20)，组末总结页给「继续下一项」。
- 次要链接: 自己选范围练习 / 模拟考试 (Phase 2 前隐藏)。
- 薄弱领域表 (最多 5 行): 领域名 (日文)、分野反白标签、頻出度 ★、正答率、「练 10 题」、「AI 分析」。排序 = 正答率低 × 出题多 (要求该领域已答 ≥ 5 题，沿用 `WEAK_MIN_ANSWERED`)。「AI 分析」= 现有 D-181 Phase B 的主动复习 (现在 quiz 首页的 `ReviewCard` / 题组页的 `ReviewLauncher`)，搬到这里，打开现有 AI 面板；行为不变。【Claude】
- 右栏: 距考试 N 天 (+ 已做 x / 2900)；三分野正答率条 + 合格线说明 (总分 600/1000 且各分野 300/1000 以上)；「今天的 3 个用语」(从今日任务的题的 `terms` 里取前 3 个、辞典里有定义的；点开去辞典)。
- 新用户 (无记录): 主按钮改为「先做 20 题摸底」(从三分野按出题比例随机抽)，其他区块显示空状态一句话。
- **頻出度 ★ 的算法**: 领域 (topic) 在 29 回过去问里的题数，按全部 63 领域的三分位 → ★☆☆ / ★★☆ / ★★★。从 `quiz_index` 计算，构建时生成，不存储新字段。【Claude】

### 6.2 练习 (Phase 1) — mockup `A4-Practice`
**设置面板** (`/practice` 无参数时): 范围 (领域 [三分野 → 领域，可多选] / 年度 / 错题本 / 到期复习 / 随机)、题数 (10 / 20 / 50 / 全部)、顺序 (按题号 / 随机)。记住上次设置，「按上次的条件继续」一键开始。从「今日」或领域表进入时跳过设置。

**一题一屏**:
- 顶部条: 分野反白标签 + 领域路径；右侧「今日复习 7/20」+ 答题卡 20 格 (○ / ×，当前格 ink 底) + 计时。
- 左 (问题面, tint 平网): 「問 N」spot 方块 (N = 原题号)；下方复习三格 + 頻出度；题干日文 (悬挂缩进、全角标点按原文)；a/b/c 子项；选项: **全部选项文字都短 (每个 ≤ 12 字且无图无表) 时 4 列横排，否则一项一行** (真题冊子的排法)；出典行「出典 令和7年度 問1」；「显示中文译文」开关 (D-186)。

## 7. 分期 (D-188 委任 → 【Claude】)

| 期 | 内容 | 用户试用点 |
|---|---|---|
| **Phase 1** | token + 字体 + AppShell (删三套 shell 与 ThemeSwitcher) · 学习记录 v2 (服务器先行) + 复习规则与每日量 (§5.4–5.5) · 今日 · 练习 (设置 / 一题一屏 / 总结 / 单题视图) · 错题本 · 设置页 (考试日、每日量、翻译默认) · 旧链接跳转 · 教科书 / 辞典 / AI 老师 **只换皮** | 电脑上每天用「今日 → 练习」 |
| Phase 2 | 模拟考试 · 学习记录页 · 复习预报 | 考前模考 |
| Phase 3 | 教科书阅读重做 + 确认题闭环 | 读单元 |
| Phase 4 | 辞典重做 · AI 老师就地化 · key 移到设置 | 查词 / 提问 |
| Phase 5 | 手机移植 (D-183) | 手机 |

**为什么 Phase 1 要连同其他页面一起换皮**: 只改做题、其他页仍是旧主题，就会重现"像两个产品"的问题 (用户最初的不满之一)。换皮只动外框和 token，不动行为，风险小。

**却下的顺序**:
| 案 | 理由 |
|---|---|
| 只先做练习，其他页下一轮再换皮 | 新旧外观并存 = 重现"两个产品" |
| 先做教科书 | 用户说目标是做题 |
| 一次性全部重做再上线 | 没有中途试用反馈；e2e 与 Rule D 一次面对全部改动，风险集中 |
| 先做手机 | D-183 |
| 不升级记录、先用 v1 做错题本 | v1 只有最近一次，"错过又答对"无法区分；以后再迁移等于做两遍 |

每期结束: 本地 + 本番 e2e、Rule D 别 type 审查、用户试用后再开下一期。
