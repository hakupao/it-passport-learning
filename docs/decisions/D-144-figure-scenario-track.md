- **Context**: S117 log §23。② の構成 = ②-a 選択肢即図 3 題 / ②-b 中問共有前文・共有図の欠落 9 exam 約 60 題 (D-141 横断適用未実施) /

- **Relates**: D-141 (中問前文の埋め込み)、D-120 (groups.json 共有図モデル、表示経路未接続)、D-134/D-135 (配信形態)。

## 決定

② は次の 4 段で進め、各段を独立に commit/push 可能な単位にする。

1. **表示層先行**: default shell の stem / choices に Markdown 表レンダリングを通す。`[表] a: X, b: Y` 型の選択肢は Markdown ではないので
   専用の描画 (キー＝値の 2 列) を定義する。データは変更しない。全量レンダリング抽検 (規則 A、N を PLAN に明記)。
2. **選択肢単位の図**: `QuizQuestion` に任意フィールド `choice_figures: {ア|イ|ウ|エ: path}` を追加。②-a 3 題は源ページから bbox 裁断
   (S99 figfix 管線を再利用) して挂図、選択肢テキストは中立 alt (「図ア」等) に戻す。三語訳は alt のみ。
3. **②-b は 2 段階**: (i) 軽量組 (同組の別題 clean に前文が既在) を決定的複製で先行 → push。(ii) 重量組は exam 単位で Extract ≠ Verify
   (S116 sharedfig 工程) → D-141 注入 → Rule D。**共有図は原則テキスト化せず題級 `figure` として各メンバーに挂ける**。テキスト化は
   図が翻訳を要する文字表を主体とする場合のみ。
4. **3 shell の統一**: 題面 (stem + figure + choices) を共有コンポーネントに抽出し、terminal / gamified / retro を `QuizSet` と同じ
   データ経路に載せる。段 1〜3 が default shell で検証済になってから着手 (純移設にする)。

## 理由

- 段 1 は約 270 題に即効し、データ変更ゼロで最低リスク。かつ段 2〜3 の産出 (構造化テキスト) の落点になる。順序を逆にすると成果が見えない。
- ②-a を全テキスト化すると 2014h26a-q086 (費用累計の階段グラフ) は失真か答え漏らしが避けられない。挂図は忠実で、3 題なら Rule A は全数。
- 共有図の挂図優先は D-141 の前提 (「図は設問ごとに figure_png 添付済」) と整合し、②-a と同じ挂図能力を使う → 機構が 1 本で済む。
- 軽量組先行は確定的処理で半日で終わり、解答不能な題を早く減らす。重量組は batch 核験並みの量で、額度事故 (S117 で 2 回) を考えると分割が要る。
- shell 統一を最後に置くのは、データ変更と前端リファクタを同じ diff に混ぜないため。

## 却下した代替案

- **表レンダリングを ② から外す**: 段 2〜3 で作る構造化テキストが学習者に届かない。
- **②-a を図→テキスト一本**: 階段グラフ等で不可能。**両方式を 3 題に併用**: 3 題に 2 機構は過剰。
- **②-b を一括**: 9 exam の源抽取 + 図裁断 + 三語 + Rule D は 1 session に収まらず、途中停止で半端が残る。
- **shell を触らない**: 467 図題が 3 shell で今も欠損しており、段 2〜3 の改善が default shell 限定になる。
- **App に中問グループ表示機構を作る** (D-141 で既却下): 前文埋め込み方式と二重化。将来やるなら埋め込み済前文を抽出源にできる。

## 実装メモ

- Markdown 描画は `QuizExplain.tsx` が既に使う `Markdown` コンポーネントを流用。stem 内の `[ a ]` 空欄 / 丸数字 / 全角空白インデント
  (擬似言語) が壊れないか、段 1 の抽検で必ず見る。
- `choice_figures` は `build-quiz-corpus` の出力スキーマと `quizCorpusInvariants.test.ts` に入れる (パスが存在する webp を指すこと、
  4 肢すべてか 0 か)。
