- **Status**: Locked (Session 114, 2026-08-28)
- **ユーザー gate**: AskUserQuestion で「4 問全てに前文を埋め込む」を選択
- **Supersedes / relates**: D-137 (Phase 2 解説生成の key-guard), D-140 (stem 腐敗の扱い),
  S107〜S113 で累積した「図/シナリオ再抽出 track」の linkage-gap 群

## 背景

IPA 過去問の **中問** (問89〜100 に置かれる連問。中問A/B/C がそれぞれ 4 問ずつ) は、
紙面では **共有記述を 1 度だけ印刷し、続く 4 問がそれを参照する**構成になっている。

一方、本アプリの quiz は **設問を 1 問ずつ単独で表示**する。中問グループの機構
(グループ ID による共有資料の同時表示) は **web app に存在しない**。

> **訂正 (S114 中の Rule A 指摘による)**: データ層には `data/ip/exams/groups.json` が
> **実在する** (Session 73 / D-120「連問共有図グループモデル」、16 グループ)。ただしその中身は
> 中問ごとの **共有「図」** (`shared_figure`: path / page_image / bbox_pct / caption) と
> `member_qids` であって、**共有「本文」は持たない**。さらに `apps/web/src/lib/quiz/` からも
> `scripts/build-quiz-corpus.mjs` からも参照されておらず、**アプリの表示経路には接続されていない**
> (S114 実測)。したがって「表示は 1 問単独」という本決定の前提は成立するが、
> 「groups 相当のファイルが存在しない」という当初の記述は誤りだったので訂正する。
> なお groups.json の登録は 16 グループにとどまり、本 batch では
> `2011h23tokubetsu-mqC` のみ登録済・`2010h22h` は 0 グループ = **カバレッジ欠落**が別途ある。

その結果、共有記述を持たない設問レコードは **単体では解答不能**になる。
S114 の generate で key-guard がこれを 8 問で捕捉した:

| exam | 中問 | 欠落していた共有記述 | 影響 |
|---|---|---|---|
| 2010h22h | C (q097〜100) | 〔S社の状況〕(1)〜(8) / 〔方針案の概要〕/ 市場シェア数値 | **4 問すべて解答不能** |
| 2011h23tokubetsu | A (q090) | 〔RFP の概要〕/ 〔X 社からの提案〕 | CPU 数・商品数/顧客数の最大値が読めない |
| 2011h23tokubetsu | B (q095, q096) | 〔関数の仕様〕/ 〔処理内容〕(1)〜(3) | 単価・上限枚数・1 割引の規則が読めない |
| 2011h23tokubetsu | C (q098) | 〔作成に関する主な指示〕(3) | 200k バイト上限が読めず「最も高い解像度」が決まらない |

S107〜S113 でも同種の linkage-gap が 8 クラスタ蓄積しており、
「図/シナリオ再抽出 track」に登録されたまま**方針が未確定**だった。

## 決定

**中問の共有記述は、そのグループに属する全設問の表示 stem に埋め込む。**

1. 対象は `stem_jp_clean` (表示層)。raw `stem_jp` は非表示のため触らない。
2. 埋め込むのは **共有記述の本文**のみ。次は埋め込まない:
   - 「中問X ○○に関する次の記述を読んで，問NN 〜 NN に答えよ。」の**見出し行**
     (corpus 規約として stem 本文には前置しない。実測 2900 問中 4 問しか持たない)
   - 分野見出し〔テクノロジ〕〔マネジメント〕〔ストラテジ〕
     (実測 25 問 = 0.86% のみ残存する OCR 残渣であり、規約は非前置)
   - **図やフローチャートの再現**。図は設問ごとに `figure_png` / `figure_page_png` として
     添付されており、テキスト再現を重複させない。
3. **zh / en も同時に埋め込む**。三言語で同じ情報量を保つ (D-136-B の用語一貫性を継承)。
4. 起草と核験は別 `subagent_type` に分ける (**Rule D**)。
   `scripts/quiz-chumon-preamble.workflow.mjs` が
   Extract (general-purpose) → Verify (pr-review-toolkit:code-reviewer) の 2 段で実行する。
5. 適用は決定的スクリプト (`quiz-chumon-preamble-apply.mjs`) が行い、
   **既に前文を持つ設問はスキップ**する (二重埋め込みの防止)。

## 検討した代替案と却下理由

### (a) 先頭問だけに前文を持たせ、残りは backlog に回す
同一 exam の中問A→q089 / 中問B→q093 が既にこの形になっており、変更範囲は最小。
**却下**: 残る 3 問は解答不能のまま出荷されることになる。
本アプリは設問を単独表示する以上、「紙面では前のページを見れば分かる」は成立しない。
S107 以降 backlog に積み続けた結果 8 クラスタが未解消のまま残った、という実績もある。

### (b) アプリ側に中問グループ機構を実装し、共有資料を同時表示する
データの重複が無く、紙面の構造に忠実。
**却下**: Phase 2 (解説の全量生成) の途中で web app のデータモデルとレンダリングを
変更するのは影響範囲が大きく、Phase 2 の完了を遅らせる。
将来グループ機構を入れる場合も、本決定で埋め込んだ前文は
「グループ資料の抽出元」としてそのまま使えるため、手戻りにはならない。

### (c) 今回は触らず、別 session で横断的に一括対応する
**却下**: 本 batch の 2 exam でまさに解答不能問が発生しており、
「見つけたのに直さずに commit する」ことになる。

## 不変条件

- `correct_answer` は変更しない。前文の復元は**答えを変えない**種類の是正である
  (key-guard も全件 `matches_key=true` と判定している)。
- 前文は原典の逐字であり、要約・言い換え・補足を加えない (Rule A の保真原則)。
- 埋め込み後は trsweep (訳文保真) と Rule A 抽検の対象に含める。
