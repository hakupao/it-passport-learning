# D-189 — UI/UX 全面再設計: A4「参考書改」の単一外観、今日軸の IA、一問一画面の練習、学習記録 v2

- **Status**: Locked (Session 132, 2026-10-23、ユーザー承認「可以的」— 設計書 + §12 の Claude 判断 4 点を含む)
- **Relates**: D-180 (学習記録 v1 + owner 同期)、D-181 (AI 先生 BYOK)、D-161 (判断委任)、D-183〜D-188 (S132 の minor 決定、本 ADR が束ねる)、D-141 (中問グループ)。
- **正本**: `docs/phase5/ui_redesign/DESIGN.md` (詳細仕様はここ。本 ADR は要点と却下案のみ)。mockup 源 = `docs/phase5/ui_redesign/mockups/A4-Practice.dc.html` / `A4-Home.dc.html`。

## 背景 — 事実 (S132 §1、本番 screenshot + コード実測)

- 首页が無い (`/[locale]` → quiz 一覧)。年度練習は 100 題の長い 1 ページ。3 theme shell (gamified / retro / terminal) で外観が揃わない。AI 先生の初画面は API key フォーム。古い文言が残る。
- `LearningRecord v1` は題ごとに最新 1 件 `{choice, correct, at}` のみ。誤答帳の再出題・理解度・復習三格・総括の比較に履歴が要る。
- `/api/learning` の `parseRecord` は `v !== 1` を拒否 (PUT 400、保存文書不正で 500) → 記録の版上げはサーバー先行でないと本番で全失敗する。
- ユーザーの要求: 「全部推翻重构」「目标就是做题，简简单单就很好，但是 AI 感太重」「全部的全部，节奏和流程交给你」、desktop 先行。

## 決定

1. **外観** = A4「参考書改」1 種のみ (D-185)。紺 `#1B2A4A` + 赤茶 `#B8501A` の 2 色刷り、BIZ UDPGothic、角丸 0〜6px、影なし、正誤は ○ / × (赤緑を使わない)。3 theme shell と ThemeSwitcher は削除 (D-188)。dark mode は本輪では作らない。
2. **IA** = 今日 / 練習 / 教科書 / 辞典 / 記録 の 5 項目 nav。AI 先生は nav に置かず就地 (解説・今日の弱点表「AI 分析」・教科書)。新 route: `/[locale]` (今日)、`/practice`、`/practice/mistakes`、`/practice/q/[qid]`、`/practice/browse`、`/mock`、`/record`、`/settings`。旧 `/quiz` の URL・片段 `#<question_id>`・`?review=1`・`&thread=` は全部新位置へ転送する。
3. **練習** = 一問一画面、即判定、既定 20 題 1 組、組末総括、誤答は自動で誤答帳 (D-187)。題面は日本語原文既定、訳は開示層 (D-186)。中問は組ごとまとめて出す。
4. **学習記録 v2** = 題ごとの作答履歴 (最近 K=10)、settings は LWW、`v2Since` は最小値。合併は「和集合 → 全順序で top-K」で可換・結合・冪等を保つ。掌握度・期日・誤答帳・leech は attempts の純関数で派生し保存しない。上線はサーバー先行 (v1/v2 両受け、新 key `learn:owner:v2`、旧 key は読むだけ)。
5. **復習規則**: 盒 [1, 3, 7, 14, 30] 日、盒 5 = 掌握。初回正解は盒 2 (7 日後に再確認)。各題は 誤答 / 到期 / 排期中 / 掌握 のどれか 1 つ。1 日の復習上限 = 誤答 + 到期 の合計 30 (10〜100)、新題 10/日 (0〜50)。v1 からの移行: 誤答は上限内で流入、正解は `v2Since` + hash mod 14 日に分散。
6. **分期**: Phase 1 = token・字体・AppShell・記録 v2・今日・練習・誤答帳・単題・設定・旧 link 転送・教科書/辞典/AI 先生の換皮 → Phase 2 模試・記録・予報 → Phase 3 教科書 → Phase 4 辞典・AI 先生就地化 → Phase 5 mobile。各 Phase 末に本番 e2e + Rule D + ユーザー試用。
7. **表示保真** (Rule A): 全 2900 題で新旧の表示関数出力を逐題比較し差 0、加えて N=30 の截図人手抽検 → `evidence/phase5/stage_07_ui/`。

## 却下した代替案

| 案 | 却下理由 |
|---|---|
| 方向 B 紙面阅读 / C データダッシュボード | ユーザーが A を選択 (做题中心、簡素) |
| A を SaaS 調のまま磨く | 「AI 感太重」。灰地白カード・青 accent・pill・kbd chip が原因 |
| 3 theme を新設計で作り直して残す | 機能ごとに 3 重実装・3 重 test、体験が揃わない |
| 練習だけ先に作り他画面は次輪で換皮 | 新旧外観の並存 =「2 つの製品」問題の再現 |
| 一括で全部作り直してから上線 | 途中試用の反馈なし、e2e と審査のリスクが集中 |
| v1 のまま誤答帳を作る | 最新 1 件では「間違えて後で正解」が区別できない、後で移行が二度手間 |
| クライアント先行で v2 を出す | 本番 `parseRecord` が v2 を 400 で拒否 |
| 復習に上限を設けない | 反目標 (積み上がるキュー) |
| IPA 公式の logo・版面を借りる | 公式の模倣になる。配色の親和性だけ借りる |
