# D-233 — zh: 教科書と UI の引号は “” (入れ子は ‘’)、quiz は C20 まで「」のまま (C26)

- 状態: **LOCKED** (2026-11-16 Session 161、委任判断 D-161、Fable 諮問を採用)
- 関連: D-232 (規則 1 の「欄に既に「があれば「」」の一文だけを本 D が置き換える。言及と注釈の区別、空白の削除、`compatText` を変えないことは引き続き有効)、D-231、C20 (quiz の zh/en 解説の忠実度)

## 規則
1. **教科書の zh content 欄と UI の zh 文言**: 引号は “”。“” の中でさらに引くときは ‘’。‘’ は “” の中だけで使い、地の文には置かない (validateV2 の `OPEN`/`CLOSE` に ‘’ は無い。地の文に置くと文の切れ目を誤る)。
2. D-232 規則 1 の引号の形は常に “” とする。統一すると「欄に「がある」場合が無くなる。
3. **quiz の zh (解説・訳 sidecar) は例外として当面「」のまま**。C20 で同じ欄を扱うとき一緒に替え、fidelity baseline の取り直しを 1 回で済ませる。方向は “” に寄せる。ただし選択肢の記号「ア」561 件と ASCII の字面「tmb」「[ a ]」775 件は、替えた後の見た目を抽出して確かめてから決める。入れ子 9 件は ‘’ にする。
4. 派生欄は個別に直さず、merge で導き直す。検査は同じ述語 (`quoteSwapOnly`) で行う。

## 結果 (S161)
- 教科書: 「 178 (中国語の句 127・`「[[jp:]]」` 51) / 119 欄 / 31 単元 → “”。入れ子は 0 件で、‘’ は出ない。派生欄の追従は施工記録に書く。
- UI: zh.json の 4 key (`pairTitle`・`pageIntro`・`threadsEmpty`・`threadDeleteLabel`) にある「 11 個。
- fixture は直さない: `v2-sample.json` は merge 試験 (`scripts/textbook-v2-merge.test.mjs`) の期待出力で、試験の入力と対になる (S161 で直したら赤になったので戻した)。`v1-frozen/` は凍結した写し。

## 根拠
- 大陆の横書きでは “” を使い、引用の中の引用は ‘’ (GB/T 15834-2011 の引号の用法。W3C clreq も同じ)。**条款番号は照合していない**ので書かない。
- コーパス: C26 施工前 (HEAD `daeade29`) の教科書 zh content 欄 (派生欄を除く) の “ は 1,615。「」は日本語原文から持ち込まれた残りで、層を分けた意図は無い。127/178 が中国語を囲む。ラベルを囲む形も `“[[jp:]]”` 159 に対して `「[[jp:]]」` 51 で、“” が多数 (Rule D が再計数。S161 初稿の 1,606・116 は数えた範囲と時点が違っていた)。
- 同じ欄に両方の形が混ざっている (strategy-01-02-u04「日语的「相関」「因果」…“相”是…」)。D-232 の「欄に「があれば「」」を残すと、新しく直すたびに「」が広がる。
- quiz は「」が 9 割を占め、隣に出る日本語原文と同じ形。替えると監査済みの解説約 8,200 欄に触れ、C20 と同じ欄で baseline を 2 回取ることになる。

## 却下
| 案 | 理由 |
|---|---|
| 現状維持 | 同じ本の中に 2 つの形が並ぶ。D-232 の分岐が「」を広げる |
| 「」= 日本語の原語、“” = 中国語 と層を分ける | データと逆 (127/178 は中国語を囲む、ラベルは “” が多数)。派生の平文欄は色が無いので区別が見えない。1 件ずつ手で判定することになる |
| 中国語の 127 だけ替え、ラベルの 51 を残す | 上の層分けと同じで、混在する欄も残る |
| 全部「」に揃える | 1,615 個を替えることになり、大陆の横書きの慣行にも反する |
| quiz も今替える | C20 と同じ欄に重なり、baseline を 2 回取る |
| quiz をユーザーへの OQ にする | D-161 では方針の裁定は主 context が行う。撤回もできる |
| UI は「」を残す (ボタン名の引用) | 大陆の UI 文言で慣行ではない。教科書の `pairTitle` は本文と同じ画面に出る |
