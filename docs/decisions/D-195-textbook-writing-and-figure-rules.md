# D-195 — 教科書 書き直しの文体・構成・図解規則 (A 骨格 + B 段階図 + C 対比・操作部品)

- **Status**: Locked (Session 134, 2026-10-27、ユーザー承認「可以，通过」)
- **Relates**: D-189 (UI/UX 再設計、DESIGN §6.4 教科書)、D-190 (文案の全面改稿は Phase 3・4 へ)、D-194 (答題画面)、Rule A (書き直し率 > 50% ⇒ 独立抽検)、D-110 (TypeScript only)。
- **樣稿**: Artifact https://claude.ai/artifact/SzjFw5SDtGcYZwbjCZAWer (Version 2、D タブ = 本 ADR の見本。A/B/C は比較用)。原稿 = S134 scratchpad `textbook-samples.html` (未入库)。

## 背景 — 事実 (S134 §1〜§4、§7)

- 現行教科書 = 244 単元 / 63 topic、用語 1417 (図あり 409、全て mermaid → svg)。単元 = intro → terms (定義・解説・比喩・記憶フック・inline_quiz・figure) → summary → challenge_questions (0〜5、画面から未接続)。
- ユーザー: 「文字太 AI 化了，我希望可以有层次，有高亮。能更简单的看懂要传达的知识」「多用图，图表，动图，甚至动画来教学」。不満 = 内容・組版・現在位置・演習との断絶の全部。
- 実例 (`strategy-01-02-u06` クロス集計表): 解説 2 段目が定型句 (「試験では…と理解しておきましょう」)、記憶フック = 定義の言い換え、intro = 7 用語を羅列した 1 文。
- 第 1〜3 輪の回答: 三語とも同等品質 / 結論先行 / 強調 4 種全部 / 比喩・記憶フック・用語内小テスト・生成図は残す (中身は書き直し) / 図解形式 4 種全部 / ja 先行 → zh・en 意訳 + 現地化 / 試行 1 topic → 一括 / 3a・3b 分割公開。
- 樣稿 A (講義ノート) / B (図解先行) / C (対比 + 操作) を提示 → ユーザー「ABC 结合」→ D 結合版 → 承認。

## 決定

1. **用語の骨格 (A)**: 各用語は固定順 **一句話 (結論) → 図 → 展開 2〜3 句 → (比喩・記法) → 考点**。一句話は 1 文で、キーワードを太字。展開は 2〜3 文まで。
2. **図は知識の型で選ぶ**:
   - 過程・手順・因果がある → **段階図 (B)**:「次へ」で進む 3〜4 step、各 step に 1 文の説明。
   - 量の関係・比率・計算がある → **操作部品 (C)**: 数値を変えると図が即時に変わる。
   - その他 → 静的図 (表・SVG)。
   - 別名・定義だけの用語 → **図なし** (図を飾りに使わない)。
   - 自動再生アニメは段階図の初回再生として使う。`prefers-reduced-motion` では最終状態へ即時。
3. **単元冒頭** = 学習目標 (「この単元で分けられるようになること」3 点前後) + **C の用語総表** (用語・一句話・変数数/形式などの比較列、折りたたみ可)。intro の長い羅列文は廃止。
4. **易混対比 (C)** は独立節にせず、組の **2 つ目の用語の直後** に並列表 (関鍵差別の行を強調) で置く。
5. **強調 4 種**: キーワード太字 (下線マーカー) / 考点マーク (「常考」等、根拠は出題データ) / 易混タグ / **日本語原語の明示** (zh・en 本文中も試験の表記を併記)。
6. **比喩・記憶フック** は残すが、定義の言い換えは禁止。記憶フックは語源・字形・対比など「定義と別の手がかり」を 1 行で。
7. **単元末** = 要点 (箇条 3〜5) → **確認題** (本単元の過去問、誤答は復習キューへ) → **「読了」ボタン** (明示操作で既読)。
8. **言語**: ja を先に書き、zh・en は意訳 + 現地化 (直訳しない)。三語とも同じ構成・同じ図。
9. **文体禁止事項** (AI 臭の除去): 定型の締め句 (「〜と理解しておきましょう」「試験では〜が問われます」の常用)、同義の言い換えの反復、1 文に用語を 3 つ以上羅列、根拠のない誇張語。

## 却下案

| 案 | 理由 |
|---|---|
| A のみ (講義ノート、静的図) | ユーザーが「動图・動画」を明示要求。過程の知識は静的図では伝わりにくい |
| B のみ (図解先行) | 全用語に段階図は過剰 (別名だけの用語にも図が要る)、制作量が膨らむ |
| C のみ (対比 + 操作) | 用語ごとの読む骨格が無く、対比表だけでは初学者が意味をつかめない |
| 易混対比を単元末に独立節 | 読んでいる文脈から離れる。2 つ目を読んだ直後が最も比較しやすい |
| 全用語に図を必須 | 図が飾りになる (現行 409 図の一部と同じ問題) |

## 影響

- 単元 JSON schema の拡張 (用語総表、易混組、図種別 static / steps / widget、要点、確認題) と描画部品 (段階図・操作部品) が要る → Phase 3 計画で設計。
- 書き直し率 > 50% のため Rule A の独立抽検が必須 (N は Phase 3 計画で決める)。三語の対照抽検を含む。
- 試行 1 topic (3〜5 単元) でこの規則を検証し、必要なら本 ADR を改訂してから一括。
